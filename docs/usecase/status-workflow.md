# Project Status Workflow

เอกสารนี้เป็น canonical workflow สำหรับหน้า overview หลังปรับ state ใหม่

## Main Flow

```text
DRAFT -> STATUS_0 -> STATUS_1 -> STATUS_2 -> STATUS_3
STATUS_3 -> STATUS_4 -> STATUS_6 -> STATUS_13
STATUS_3 -> STATUS_5 -> STATUS_7 -> STATUS_13
```

`STATUS_8`, `STATUS_9`, และ `STATUS_10` เป็น legacy/deprecated สำหรับ workflow หลักหน้า overview และไม่ควรถูกใช้ใน action ใหม่

## State Meaning

| State       | ความหมาย                                                     | เจ้าของ action หลัก       |
| ----------- | ------------------------------------------------------------ | ------------------------- |
| `DRAFT`     | เจ้าของโครงการจัดทำแบบร่าง                                   | เจ้าของโครงการ            |
| `STATUS_0`  | เสนอหัวหน้าภาควิชา                                           | หัวหน้าภาควิชา            |
| `STATUS_1`  | งานวิจัยตรวจสอบ/แก้ไขข้อมูล                                  | งานวิจัย                  |
| `STATUS_2`  | งานวิจัยตรวจเรียบร้อย รอหัวหน้าฝ่ายวิจัยอนุมัติเข้าที่ประชุม | หัวหน้าฝ่ายวิจัย          |
| `STATUS_3`  | รอ/เสนอเข้าที่ประชุมและเลือกเส้นทางหลังประชุม                | งานวิจัย                  |
| `STATUS_4`  | ผ่านมติคณะกรรมการบริหารคณะวิทยาศาสตร์ รอข้อมูลหลังมติ        | งานวิจัย, งานแผน, งานคลัง |
| `STATUS_5`  | ผ่านมติคณบดี รอข้อมูลหลังมติ/ไฟล์อนุมัติ                     | งานวิจัย, งานแผน, งานคลัง |
| `STATUS_6`  | อนุมัติแล้ว ดำเนินโครงการได้ สายมติคณะกรรมการฯ               | ทุกหน่วยงานตามหน้าที่     |
| `STATUS_7`  | อนุมัติแล้ว ดำเนินโครงการได้ สายมติคณบดี                     | ทุกหน่วยงานตามหน้าที่     |
| `STATUS_13` | ปิดโครงการ                                                   | งานวิจัย                  |

## Release Rules

`STATUS_4 -> STATUS_6` ต้องมีข้อมูลหลังมติครบ:

- งานคลังกรอก `vendorCode`
- งานแผนกรอก `costCenter`
- งานวิจัยกดปล่อยดำเนินโครงการ และระบบออก `projectCode`

`STATUS_5 -> STATUS_7` ต้องมีข้อมูลครบเหมือน `STATUS_4` และต้องมีไฟล์/ลิงก์อนุมัติคณบดี

ก่อน `STATUS_6/7` ถ้ายังไม่มี `projectCode` ให้ UI แสดงว่า `ยังไม่อนุมัติ`

## Closure Rules

`STATUS_6/7 -> STATUS_13` ต้องมี:

- รายงานดำเนินโครงการหรือ `docLink`
- งานวิจัยยืนยันข้อมูลครบ
- งานกายภาพยืนยันข้อมูลครบ ถ้ามีข้อมูลกายภาพที่เกี่ยวข้อง
- งานคลังยืนยันปิดการเงิน (`FINANCE`)

## Budget Revision Sub-flow

การขอแก้ไขงบประมาณหลังอนุมัติแล้วเป็น sub-flow แยก ไม่เขียนทับงบหลักจนกด apply

```text
BR_DRAFT -> BR_SUBMITTED -> BR_RESEARCH_CHECKED -> BR_WAITING_MEETING
BR_WAITING_MEETING -> BR_BOARD_APPROVED -> BR_APPLIED
BR_WAITING_MEETING -> BR_DEAN_APPROVED -> BR_APPLIED
```

- ผ่านมติแก้งบตามเกณฑ์ = ผ่านมติคณะกรรมการบริหารคณะวิทยาศาสตร์
- ผ่านมติแก้งบแบบอนุมัติพิเศษ = ผ่านมติคณบดี
- ถ้า apply สายคณบดีและ project เดิมอยู่ `STATUS_6` ให้เปลี่ยนเป็น `STATUS_7`
